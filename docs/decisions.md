# 決めたこと

## 2026-10-01

### 1. レベルは「件数 × 任せられる度」で出す
- 画面イメージでは、お客様対応ドラフトがレベル5なのに任せられる度22%で、見る人が迷う。
- 件数と任せられる度の両方を満たしたときに上がる形にした。下がることもある。
- 条件の表は [default_template.md](default_template.md#レベル)。

### 2. 「修正なし」は自動で数える
- AIの案と実際に使われた文を比べて自動で区分する。人がボタンで付ける形は押し忘れで記録が偏るため採らない。
- そのために、個別層に「出力の出口」（I10）を必須の項目として入れた。

### 3. 固定層の変更は、複製済みのAI社員に自動で反映する
- カードに版の番号（デフォルト v1.0 など）を出す。
- 変更の後は任せられる度の動きを見る（default_template.md「固定層を変えるとき」）。

### 前提
- AI社員の頭脳は Claude を初期値にし、差し替えられる作りにする。
- 新しい会社のチャットツール・AIの契約・業務の中身は入社後に埋める（テンプレート内の〔 〕の箇所）。
- 前職・取引先のコードや業務データは持ち込まない。持ち込むのは考え方だけ。

### 4. 最終的な目的は「テンプレートを外へ持ち運べること」
- テンプレート（`template/`）と会社のデータ（`data/`）を分けた。持ち運ぶのは `template/` だけ。
- 画面から1つのファイル（テンプレートパック）に書き出し、別の環境で読み込める。依頼の中身は入れない。
- 読み込みで既存のAI社員は消さない。同じ名前のAI社員は追加しない。

### 5. カレンダーでAI社員の仕事を予約する
- 予定＝AI社員・依頼文・日時・繰り返し（なし／毎日／平日／毎週／毎月）・終わりの日。
- 時刻が来たらAIが案を作る。作るのは案までで、使うかどうかは人が決める（固定層のとおり）。
- サーバーが止まっていた間の回は、次の起動時に一番新しい1回だけ作る。まとめて作ると費用が積み上がるため。
- 予定は会社ごとのデータ（`data/schedules.json`）。テンプレートパックには入れない。

### 6. 画面は「使う人」のもの。管理はシステム側（コマンド）
- 画面のメニューは AI社員一覧・カレンダー・稼働ログ だけ。
- AI社員の追加・変更・削除、テンプレートの編集・版上げ・持ち出し・持ち込みは `npm run agent` / `npm run template` で行う。
- 「任せられる度」は画面では「経験値」と呼ぶ。数え方は**累計**（修正なしで使われた割合）。直近30日から変えた。累計なのでレベルはほぼ下がらない。直近を見たいときは `classify.trustWindowDays` に日数を入れる。
- カレンダーは別に作った運用カレンダーのレイアウトを流用した（ユーザーの判断）。レイヤー＝AI社員。
